# 交叉复核指引（给 DeepSeek / 千问 / 豆包 的复核任务书）

## 复核原则

**修正记录是信任资产，不是耻辱柱。**复核模型（包括本项目主力模型 Kimi K3）在复核中犯的归因错误，被领域专家依据原始证据纠正后，按"明示修正而非抹除"原则留痕（实例见《DeepSeek三次复测日志》发现A的"审计修正"段：K3曾将模型思维链表述误判为"事后抢功"，被测试者指正后撤回并保留痕迹）。**audit/ 目录里的修正记录越多，仓库可信度越高，而不是越低**——每一条修正都是"证据优先于立场"的活演示。这一条同时适用于复核者与被复核者。

**不要让复核模型重新打分**——那只会再产生一轮印象分。复核的任务是核对"引证 vs 原文"：

> 你是一名严格的评审员。我将提供：(1) 一份LLM对话实录；(2) 一份评分表。评分表中每条评分都附了"轮次+原文引证"。请逐条核对：①引证文字是否真实存在于实录的对应轮次；②引证是否支持该评分（有没有断章取义）；③实录中是否存在推翻该评分的其他证据。只回答这三件事，不要重新打分。

## 操作步骤

1. **本指引不提供给复核模型。**复核模型只收到三样东西：评审提示词 + 一份对话实录 + 完整评分表。本文档（尤其"重点抽查清单"）是测试者的导演手册——清单列明了历史出错位置，给复核者看会锚定其注意力，既污染独立判断，也使复核者丧失"自主发现问题"的证明力；清单用于拿到结果后人工对照（复核模型漏查清单条目=其遗漏，记录在案）。
2. 每次会话=**一份实录 + 完整评分表**，在评审提示词末尾追加列限定："只核对【模型名】这一列的评分及涉及该模型的引证，其他列忽略。"（不需要手工拆列——整表仅百余行，拆列的复制粘贴反而引入人为错位风险；列限定即可隔离。六个模型共六次会话。）
3. 要求复核模型对每条输出三档结论：✅引证属实且支持评分 / ⚠️引证属实但解读有争议 / ❌引证不存在或不支持；
4. 三家复核结果分歧的条目，升级给你（人工仲裁）——这就是你自己的"双人核对"流程；
5. 复核结论附进 GitHub 仓库 `audit/` 目录，作为"多judge交叉核验"的实证记录。
